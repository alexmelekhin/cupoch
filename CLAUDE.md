# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cupoch` is a CUDA reimplementation of Intel Open3D for robotics (point clouds, registration, KinectFusion, odometry, collision, path planning). Shipped primarily as a `pip` wheel built from C++/CUDA via pybind11. Self-declared **Alpha**.

## Build / test / package

Requires CUDA + a recursive clone (`git clone --recurse`; deps are git submodules). Out-of-tree build:

```sh
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release   # add -DUSE_RMM=OFF to drop the RAPIDS allocator
make -j                               # builds all cupoch_<module> libs + unittests
make pip-package                      # build wheel  (make install-pip-package = build+pip install)
```

- Tests: googletest, target `unittests` (`make unittests && ./bin/unittests`). Single test: `./bin/unittests --gtest_filter=PointCloud.*`. Test data dir is wired via `TEST_DATA_DIR` (`examples/testdata/`).
- **CI never builds or runs `unittests`** before publishing to PyPI — do not assume green CI means tests pass. Run them locally.
- Sources are `file(GLOB_RECURSE ...)` with **no `CONFIGURE_DEPENDS`**: after adding/removing a source file you must re-run `cmake` or it won't compile.
- `CMAKE_CUDA_ARCHITECTURES` defaults to `86`; override for other GPUs. `USE_RMM`/`BUILD_*` options are in the root `CMakeLists.txt`. On Windows, unit tests and RMM are force-disabled.

## Architecture (the parts that span files)

- **Layered module DAG** under `src/cupoch/<module>/`, each a static lib `cupoch_<module>`: `utility` → {`camera`,`knn`} → `geometry` → {`registration`,`odometry`,`integration`,`collision`,`io`,`imageproc`} → {`planning`,`kinematics`,`kinfu`} → `visualization`. No cycles. `geometry` is the hub; `utility` is the foundation. CMake `target_link_libraries` under-declares real deps — it only compiles because root `include_directories(src)` exposes all headers.
- **GPU storage = struct-of-arrays.** Geometry holds `utility::device_vector<Eigen::Vector3f>` members (e.g. `PointCloud::points_`, public). `device_vector<T>` is a compile-time alias: `rmm::device_vector` if `USE_RMM` else `thrust::device_vector` (`utility/device_vector.h`). **Toggling `USE_RMM` changes the public ABI.**
- **Compute = Thrust functors.** Algorithms are `__device__` functors dispatched via Thrust over zip/counting iterators. Reusable toolkit in `utility/helper.h` (`make_tuple_begin`, `enumerate_begin`, `add_tuple_functor`); `ComputeJTJandJTr` in `utility/eigen.inl` is the shared Gauss-Newton core for registration/odometry.
- **`.h` / `.inl` / `.cu` templating idiom.** Generic bodies live in `.inl`; each `.cu` ends with **hand-written explicit instantiation lists** (e.g. `knn/kdtree_flann.cu`). Adding a new template type means manually adding instantiation lines or you get distant linker errors.
- **CPU↔GPU transfer = `Host*` mirror structs** (`HostPointCloud`, etc. in `io/class_io/`) with per-type `ToDevice`/`FromDevice`/`Clear`. Boilerplate is duplicated per geometry type, not generalized.
- **Geometry hierarchy** is classic runtime-OO, base templated on Eigen types: `Geometry` → `GeometryBase<Vec,Mat,Trans>` (`GeometryBase3D`/`2D`, `GeometryBaseXD<Dim>`) → concrete types; `MeshBase`→`TriangleMesh`, `DenseGrid<V>`→`OccupancyGrid`. **Destructors are intentionally non-virtual** (`__host__ __device__`, no vtables for device code) — do not "fix" them to virtual; pass concrete types or `shared_ptr`, never `delete` through a base pointer.
- **Python layer** `src/python/cupoch_pybind/` mirrors the C++ module tree, hand-written. numpy↔GPU via `device_vector_wrapper` (explicit copy; `.cpu()` to read back) plus a zero-copy **DLPack** path. Pure-Python `src/python/cupoch/__init__.py` is a 3-line re-export. `.pyi` stubs generated by `make generate-stubs`.

## Gotchas

- **`utility::LogError` does NOT throw or abort** (`utility/console.h` — just `spdlog::error`). Error paths log and fall through with invalid values; failures do not propagate to callers/Python. Validate inputs explicitly; do not rely on `LogError` for control flow.
- Public headers pull in Thrust/Eigen/CUDA — any C++ consumer must compile with `nvcc` and a matching `USE_RMM`. There is no host-only ABI.
- File parsers under `io/file_format/` are Open3D-derived and trust header fields (sizes/counts) — treat untrusted input files as a memory-safety risk.
- Two packaging configs disagree: `src/python/setup.py` (setuptools, actually builds the wheel) vs `src/python/pyproject.toml` (poetry, the documented intent). `docs/index.md` is stale; `README.md` is the current source of truth.
